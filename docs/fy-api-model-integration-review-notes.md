# Fy-api 主流模型接入文档审稿与维护说明

> 更新时间：2026-06-15  
> 用途：内部审稿、后续维护、厂商附录拆分参考。不要把本文直接作为客户接入文档发布。

## 定位判断

Fy-api 的文档应该写成“统一网关接入文档”，而不是“厂商原生 API 文档合集”。

核心原因：

1. 客户调用的是 TraceNex / Fy-api 网关，不是直接调用 OpenAI、Anthropic、Google、火山、阿里等厂商。
2. 网关负责统一鉴权、路由、分组、限流、日志、计费、错误追踪。
3. 不同厂商的差异应通过协议选择、字段映射、`metadata` 透传和厂商附录表达。
4. 主文档只需要让客户选对端点、填对参数、知道怎么查任务和排障。

## 建议的信息架构

| 区块 | 目标 | 建议内容 |
|---|---|---|
| 快速开始 | 让开发者 3 分钟跑通 | Base URL、Bearer Token、chat curl、错误返回格式 |
| 协议选择器 | 避免客户走错端点 | OpenAI Chat、Responses、Claude Messages、Gemini Native、Image、Video、Audio、Embedding、Rerank、Realtime |
| 模型族接入 | 解释主流模型怎么接 | OpenAI/Azure、Claude、Gemini/Vertex、DeepSeek、Qwen/通义、Doubao/火山、Moonshot、智谱、MiniMax、Cohere/Jina、图片/视频模型 |
| 参数字典 | 统一参数口径 | 每个协议的必填、常用、可选、谨慎参数 |
| 调用示例 | 可复制 | curl、Python、JavaScript，优先 curl |
| 管理员接入流程 | 给运营配置渠道 | 渠道类型、Key、Base URL、模型名、分组、价格、测试 |
| 排障手册 | 降低支持成本 | request_id、日志查询、常见状态码、模型无权限、余额不足、任务超时 |
| 版本与限制 | 避免误解 | 哪些 OpenAI 端点未实现，哪些参数由上游决定 |

## 模型族附录模板

每个模型族附录建议按同一套模板写，便于销售、交付和客户快速理解：

1. 快速结论：调用方式、鉴权、核心接口、推荐模型。
2. 接口地址：提交、查询、下载/取结果、兼容旧路径。
3. 支持模型：列模型名、定位、是否推荐、是否可映射。
4. 最小示例：给一个能跑通的 curl。
5. 返回示例：提交成功、处理中、成功、失败。
6. 状态枚举：客户如何轮询，轮询间隔是多少。
7. 请求字段说明：基础字段、尺寸/分辨率映射、默认值、冲突规则。
8. 多模态输入：图片、视频、音频、文件怎么传。
9. 厂商原生参数：通过 `metadata` 或专用字段透传。
10. 高级能力说明：如真实人脸素材准备、1080p pipeline、缓存、工具调用。
11. 接入注意事项：必填、不要冲突、异步任务、URL 可访问性。
12. 官方参考：只放必要链接，避免客户在主流程里迷路。

## 页面设计建议

- 首屏不要做营销页，直接放“接入 Fy-api 需要三件事”：平台地址、API Key、模型名。
- 左侧做粘性目录，右侧正文，方便客户跳转到协议。
- 每个协议先给“什么时候用”，再给参数表，再给示例。
- 参数表按“必填 / 常用 / 高级 / 透传”分组，避免把所有字段平铺。
- 所有示例都使用占位符：`https://api.example.com`、`sk-...`、`gpt-4o-mini`，避免泄露真实生产信息。
- 视频任务接口必须单独强调：提交后返回 task id，需要轮询，不是同步返回视频。

## 生产可用标准

上线前，主文档至少要满足下面几条：

- 客户能从第一页直接找到 `base_url`、`Authorization`、`model` 和最常用示例。
- 每个协议都给出明确端点和最少一个可复制样例。
- 视频任务明确写出提交、查询、下载三步。
- 模型名写成示例值，并明确最终以平台模型广场为准。
- 运营能从文档里找到渠道创建、价格配置、验证和排障方法。
- 不把厂商原生参数误写成 Fy-api 必填项。

## 长期维护原则

正式维护时建议遵循三层结构：

第一层是客户快速接入：只讲 Base URL、Token、模型名、最常用的 Chat/Image/Video 三个示例。客户能复制即用。

第二层是协议选择：说明 OpenAI SDK 用户怎么填，Anthropic SDK 用户怎么走 `/v1/messages`，Gemini SDK 用户怎么走 `/v1beta/models/*`，视频用户为什么必须使用异步任务。

第三层是运营/管理员接入：说明内部人员怎么把新模型挂到平台，包括渠道、模型名、价格、测试、日志排查。

主文档只写 Fy-api 统一参数和常用差异。厂商深度参数放到厂商附录，例如“阿里 Wanx 视频参数附录”“Veo 参数附录”“Claude beta 字段附录”。
