API 接口文档

API 接口文档

API 网关的 Chat Completions、Image Generation、Video Generation、Responses 和 Models 协议完整参考。兼容 OpenAI 格式，所有端点通过统一 Base URL 鉴权、路由和计费。

概览

兼容 OpenAI 的 API 接口。客户使用统一 Base URL 和 API Token，平台负责鉴权、请求转发、用量记录和计费。

端点协议返回OpenAI 参考
POST /v1/chat/completions OpenAI Chat Completions 同步 JSON 或 SSE 流式 Chat API 文档
POST /v1/images/generations OpenAI Images 同步 JSON Images API 文档
POST /v1/images/edits OpenAI Images Edits 同步 JSON (multipart/form-data) Images Edits 文档
POST /v1/responses OpenAI Responses 同步 JSON 或 SSE 流式 Responses API 文档
POST /v1/video/generations Video Generation（异步任务） 同步 JSON（返回 task_id） OpenAI 兼容 · 多供应商适配
GET /v1/video/generations/:task_id Video Generation（查询任务） 同步 JSON 轮询任务状态和结果
POST /v1/videos OpenAI Videos（异步任务） 同步 JSON（返回 task_id） OpenAI Videos API
GET /v1/videos/:task_id OpenAI Videos（查询任务） 同步 JSON 轮询任务状态和结果
GET /v1/models OpenAI Models 同步 JSON Models List API
GET /v1/models/:model OpenAI Models 同步 JSON 检索单个模型
GET /v1/dashboard/billing/subscription OpenAI Billing 同步 JSON 订阅信息查询
GET /v1/dashboard/billing/usage OpenAI Billing 同步 JSON 用量和消耗查询

认证

所有端点使用 Bearer Token 认证。在平台 令牌管理 中创建 sk- 开头的令牌。

Authorization: Bearer sk-你的令牌
令牌可绑定用户分组、额度上限、过期时间、模型权限和 IP 白名单。错误模型名或权限不足通常导致 400 或 无可用模型。

Base URL

所有 API 端点基于平台首页展示的服务器地址。登录平台后进入左侧导航 首页，在首页状态信息或接口信息区域复制 服务器地址 / API 地址；如果首页未显示该信息，请联系平台支持获取服务器地址。

{服务器地址}

使用 OpenAI SDK 时，baseURL 设置为 {服务器地址}/v1。注意服务器地址末尾不要重复添加斜杠；如果平台首页展示的地址已经带有 /v1，SDK 中直接使用该完整地址。

获取路径：登录平台 -> 左侧导航 首页 -> 复制首页展示的 服务器地址 / API 地址。令牌仍然在 令牌管理 中创建。

Chat Completions

POST /v1/chat/completions

根据对话历史创建模型响应。支持流式和非流式，兼容 OpenAI Chat Completions API。新项目也可以优先评估 Responses API。

请求参数

参数类型必填默认说明
modelstring是—模型 ID，如 gpt-4o、deepseek-chat
messagesMessage[]是—对话消息列表，详见 Message 结构
temperaturenumber否1采样温度，范围 0–2
top_pnumber否1核采样，范围 0–1
ninteger否1生成数量，≥ 1
streamboolean否false是否 SSE 流式响应
stream_optionsobject否—含 include_usage (boolean)，在流式最后一个 chunk 返回 usage
stopstring | string[]否—停止序列
max_tokensinteger否—最大生成 Token 数
max_completion_tokensinteger否—最大补全 Token 数（与 max_tokens 二选一）
presence_penaltynumber否0范围 -2 到 2
frequency_penaltynumber否0范围 -2 到 2
logit_biasobject否—token_id → bias 映射
logprobsboolean否false是否返回输出 token 的 log probability（需模型支持）
top_logprobsinteger否—每个输出 token 返回的候选 logprob 数量；使用时通常需同时设置 logprobs:true
userstring否—终端用户标识，用于上游风控和审计
safety_identifierstring否—OpenAI 安全标识符；本平台默认过滤，需渠道开启 allow_safety_identifier
prompt_cache_keystring否—用于上游 prompt cache 命中优化；也可作为渠道粘性路由键来源
prompt_cache_retentionstring否—OpenAI prompt cache 保留策略，如 "in_memory" / "24h"，按上游支持生效
storeboolean否—是否允许上游存储输出；本平台默认允许透传，渠道开启 disable_store 后会过滤
metadataobject否—请求元数据，按上游兼容情况透传
predictionobject否—OpenAI 预测输出提示，用于低延迟编辑/补全场景，按模型支持生效
toolsTool[]否—工具定义，详见 Tools 结构
tool_choicestring | object否—"none" / "auto" / "required" 或指定函数
parallel_tool_callsboolean否—是否允许并行工具调用，按模型/渠道支持生效
functionsFunction[]否—旧版函数调用字段，已被 OpenAI 标记为 deprecated；建议使用 tools
function_callstring | object否—旧版函数调用选择字段，已被 tool_choice 替代
response_formatobject否—{"type":"text"} / {"type":"json_object"} / {"type":"json_schema","json_schema":{...}}
seedinteger否—随机种子，用于可复现输出
reasoning_effortstring否—推理强度："low" / "medium" / "high"（推理模型适用）
verbositystring否—输出详略控制："low" / "medium" / "high"，按模型支持生效
service_tierstring否—OpenAI 服务层级；可能影响成本，本平台默认过滤，需渠道开启 allow_service_tier
modalitiesstring[]否—响应模态："text" / "audio"
audioobject否—音频配置：{"voice":"alloy","format":"mp3"}
web_search_optionsobject否—Chat Completions Web Search 配置，按 OpenAI 兼容渠道和模型支持生效
兼容说明：请求字段会先由网关解析，再按渠道转换或透传。service_tier、safety_identifier、context_management 默认会被过滤；store 默认允许透传但可由渠道禁用；全局或渠道开启 pass-through body 后会跳过这些保护性过滤。不同上游模型对 prediction、verbosity、web_search_options、音频输出和 logprobs 的支持不一致，不支持时以上游返回为准。OpenAI 官方 Chat Completions 中的请求级 moderation 配置当前未在本平台通用 DTO 中启用，普通兼容请求不承诺透传。

Message 结构

字段类型必填说明
rolestring是"developer" / "system" / "user" / "assistant" / "tool" / "function"；新版 OpenAI 模型建议用 developer 替代旧 system 指令层级
contentstring | MessageContent[]是纯文本字符串，或多模态内容数组
namestring否发送者名称
tool_callsToolCall[]否助手消息中的工具调用，支持 function tool；部分上游还支持 custom tool
function_callobject否旧版函数调用字段，兼容保留
tool_call_idstring否tool 角色消息中回传的工具调用 ID
reasoning_contentstring否推理模型的思考内容

MessageContent 多模态内容块

当 content 为数组时，每项包含 type 字段标识内容类型：

type关键字段说明
texttext (string)纯文本内容
image_urlurl (URL 或 data:image/...;base64,...)，detail ("low"/"high"/"auto")图片输入，用于多模态视觉理解
input_audiodata (base64)，format ("wav"/"mp3")音频输入
filefilename / file_data / file_id文件输入
video_urlurl (string)视频输入

Tools & 工具调用

Tool 定义：

字段类型说明
typestring工具类型，如 "function"
function.namestring函数名
function.descriptionstring函数描述
function.parametersobjectJSON Schema 格式的参数定义

ToolCall（助手返回）：

字段类型说明
idstring工具调用 ID
typestring"function"
function.namestring函数名
function.argumentsstringJSON 字符串形式的参数
工具调用流程：客户端发送 tools 定义 → 助手返回 tool_calls → 客户端执行函数 → 以 role:"tool" + tool_call_id 回传结果。

响应格式

字段类型说明
idstring响应唯一 ID
objectstring"chat.completion"
createdintegerUnix 时间戳
modelstring实际使用的模型
choicesarray每项含 index、message、finish_reason
usageUsageToken 用量详情
system_fingerprintstring系统指纹

finish_reason 枚举：

stop length tool_calls function_call content_filter

Usage（Token 用量）

字段类型说明
prompt_tokensinteger提示词 Token 数
completion_tokensinteger补全 Token 数
total_tokensinteger总 Token 数
prompt_tokens_detailsobject含 cached_tokens、text_tokens、audio_tokens、image_tokens
completion_tokens_detailsobject含 audio_tokens、reasoning_tokens、accepted_prediction_tokens、rejected_prediction_tokens 等

流式响应

设置 "stream": true 后，响应以 SSE (Server-Sent Events) 格式逐块返回。每块为 data: {"object":"chat.completion.chunk", ...}\n\n。

字段类型说明
idstring响应 ID
objectstring"chat.completion.chunk"
createdinteger时间戳
modelstring模型名
choices[0].deltaobject增量内容：role、content、reasoning_content、tool_calls
choices[0].finish_reasonstring | null结束时非 null
usageUsage仅当 stream_options.include_usage:true 时在最后一个 chunk 返回

调用示例

基础对话

curl -X POST {服务器地址}/v1/chat/completions \
  -H "Authorization: Bearer sk-你的令牌" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      {"role": "system", "content": "你是一个有帮助的助手。"},
      {"role": "user", "content": "介绍一下 API 网关"}
    ]
  }'

curl -N -X POST {服务器地址}/v1/chat/completions \

  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "写一个 Go HTTP server"}],
    "stream": true,
    "stream_options": {"include_usage": true}
  }'

多模态图片理解

Video Generation

POST /v1/video/generations

根据文本提示词或参考图生成视频。异步任务模式：提交后返回 task_id，通过查询接口轮询任务状态和结果。兼容 OpenAI Videos API，支持 Sora、Kling、Hailuo、Vidu、Jimeng、Doubao、Ali Tongyi Wanxiang、Gemini Veo 等模型。

异步任务流程：提交生成任务 → 获得 task_id → 轮询 GET /v1/video/generations/:task_id → status:"completed" 时获取视频 URL。

端点列表

方法路径说明
POST/v1/video/generations提交视频生成任务
GET/v1/video/generations/:task_id查询任务状态和结果
POST/v1/videosOpenAI 兼容视频生成
GET/v1/videos/:task_idOpenAI 兼容任务查询
POST/v1/videos/:video_id/remix视频再创作（Sora 等支持）

请求参数

参数类型必填默认说明
modelstring是—模型名，如 sora-2、kling-v1、hailuo-2.3
promptstring是—视频描述提示词
imagestring否—参考图 URL 或 Base64（图生视频）
durationnumber否5视频时长（秒），常见 5 或 10
widthinteger否—视频宽度（像素），如 1920
heightinteger否—视频高度（像素），如 1080
fpsinteger否—帧率，如 30
seedinteger否—随机种子，用于可复现输出
ninteger否1生成视频数量
response_formatstring否—"url" 返回视频 URL
userstring否—终端用户标识，用于上游风控和审计
注意：视频生成是异步操作，客户端超时建议设置 10 分钟以上。不同供应商支持的参数不同（如分辨率、帧率、时长等），具体以供应商文档为准。

响应格式

提交任务返回：

{
  "task_id": "task_abc123def456",
  "status": "queued"
}

查询任务返回：

{
  "id": "task_abc123def456",
  "object": "video",
  "model": "sora-2",
  "status": "completed",
  "progress": 100,
  "created_at": 1710000000,
  "completed_at": 1710000180,
  "seconds": "5",
  "size": "1920x1080",
  "metadata": {
    "url": "{视频URL}"
  }
}

任务状态枚举：

queued in_progress completed failed

  }'

查询任务状态

curl -X GET {服务器地址}/v1/video/generations/task_abc123def456 \

图生视频

Model List

GET /v1/models

列出当前用户可用的模型列表。兼容 OpenAI Models API，同时支持 Anthropic 和 Gemini 兼容响应格式（通过请求头自动识别）。

方法路径说明
GET/v1/models列出所有可用模型（OpenAI / Anthropic / Gemini 格式）
GET/v1/models/:model检索单个模型详情

调用示例

curl -X GET {服务器地址}/v1/models \
  -H "Authorization: Bearer sk-你的令牌"

OpenAI SDK

const models = await client.models.list();
for (const model of models.data) {
  console.log(model.id);
}

Anthropic 格式

curl -X GET {服务器地址}/v1/models \
  -H "x-api-key: sk-你的令牌" \
  -H "anthropic-version: 2023-06-01"

Image Generation

POST /v1/images/generations

根据文本提示词生成图片。兼容 OpenAI Images API，支持 DALL-E、GPT Image、Gemini Imagen / image-preview、通义万相、火山、腾讯 AIArt 等模型。

请求参数

参数类型必填默认说明
modelstring是—模型名，如 gpt-image-2、gpt-image-1.5、gpt-image-1、gpt-image-1-mini、dall-e-3、imagen-*、gemini-*-image*
promptstring是—图片描述提示词。GPT Image 官方上限更高，DALL-E 2/3 上限较低；实际限制以上游模型为准
ninteger否1生成张数，通常 1–10；dall-e-3 官方仅支持 1；部分上游会忽略或限制该值
sizestring否"1024x1024"图片尺寸。DALL-E 2：256x256 / 512x512 / 1024x1024；DALL-E 3：1024x1024 / 1792x1024 / 1024x1792；GPT Image 标准尺寸含 1024x1024 / 1536x1024 / 1024x1536 / auto；gpt-image-2 官方支持符合限制的任意 WIDTHxHEIGHT。Gemini 适配会把常见尺寸映射为 aspect ratio 或 imageSize，见下方说明
qualitystring否"auto"质量档位："auto" / "high" / "medium" / "low" 或 DALL-E "standard" / "hd"
stylestring否—DALL-E 3 风格："vivid" / "natural"
response_formatstring否—"url" 或 "b64_json"。OpenAI GPT Image 官方始终返回 base64；Azure gpt-image-* / chatgpt-image-latest 不支持此字段，本平台会在 Azure GPT image 请求中删除它
backgroundstring否—背景策略："auto" / "transparent" / "opaque"
moderationstring否—内容审核："auto" / "low"
output_formatstring否—输出格式："png" / "jpeg" / "webp"
output_compressioninteger否100压缩质量 0–100，仅对 GPT Image 的 jpeg / webp 输出有效
streamboolean否false是否流式生成（需上游支持）
partial_imagesinteger否—流式中间图数量，官方范围 0–3，仅 stream:true 时使用
userstring否—终端用户标识
注意：部分图片模型不支持 response_format。腾讯 AIArt 服务默认返回 b64_json，只有显式传 response_format:"url" 时才返回 COS URL。

渠道兼容与 Gemini 图片模型映射

渠道/模型网关行为参数映射
OpenAI / Azure GPT ImageOpenAI 兼容透传；非流式使用统一 image response，流式使用 OpenAI image SSE 事件Azure gpt-image-* / chatgpt-image-latest 会删除 response_format，避免 Azure 上游拒绝
Gemini imagen*转为 Gemini Imagen models/{model}:predictsize 转 aspectRatio：1024x1024→1:1、1536x1024→3:2、1024x1536→2:3、1792x1024→16:9、1024x1792→9:16；quality=high/hd/2K 转 imageSize=2K，auto/medium/low/standard/1K 转 1K
Gemini image-preview：gemini-3-pro-image*、gemini-3.1-flash-image*、gemini-2.5-flash-image转为 Gemini generateContent，请求包含文本 prompt，并要求 responseModalities=["TEXT","IMAGE"]n 转 candidateCount；size 转 imageConfig.aspectRatio 或 imageConfig.imageSize；2048x2048 转 2K，4096x4096 转 4K；这类模型版本默认钉到 v1beta，原生 Gemini /v1beta/... 入口会保留客户端路径版本
腾讯 AIArt当 Tencent 渠道 base_url 为 aiart.tencentcloudapi.com 时，转为腾讯 AIArt 同步轮询流程size / quality / response_format 按腾讯支持范围转换；安全命中会返回 OpenAI 风格 moderation_blocked

响应格式

字段类型说明
createdintegerUnix 时间戳
dataImageData[]生成的图片数组
backgroundstringOpenAI GPT Image 可能返回实际背景策略
output_formatstringOpenAI GPT Image 可能返回实际输出格式
qualitystringOpenAI GPT Image 可能返回实际质量档位
sizestringOpenAI GPT Image 可能返回实际尺寸
usageobject部分 OpenAI GPT Image 模型返回图片 token 用量；本平台会用于图片模型日志和计费结算

Image Edits

POST /v1/images/edits

基于参考图和可选遮罩编辑图片，兼容 OpenAI Images Edits API。OpenAI 官方新接口支持 JSON 形式的 images / mask 引用对象；本平台同时兼容传统 multipart/form-data 文件上传。

请求参数

参数类型必填说明
imagesarray<object> | string[]JSON 必填OpenAI 官方 JSON 形式的输入图片列表，每项可为 {"image_url":"https://..."}、{"image_url":"data:image/...;base64,..."} 或 {"file_id":"file-..."}。GPT Image 官方最多支持 16 张。OpenAI 兼容渠道会透传官方对象数组；Gemini image-preview 转换目前只解析 URL / data URL / base64 的字符串或字符串数组，不解析 file_id，也不解析官方对象数组内的 image_url
imagefile | string | string[]multipart 必填传统上传字段。multipart 可重复传 image、image[] 或 image[0]；JSON 兼容可传 URL、data URL、裸 base64 或字符串数组，主要用于 Gemini image-preview 适配。需要同时兼容 OpenAI 和 Gemini 时，优先使用 multipart 多图上传
promptstring是编辑描述，说明要对图片做什么修改
maskfile | object | string否遮罩图片。OpenAI JSON 形式为 {"image_url":"..."} 或 {"file_id":"..."}；multipart 形式为文件。Gemini image-preview 会把 mask 作为额外图片 part 并加提示文本，语义效果以上游模型为准
modelstring否模型名。OpenAI 官方 edit 支持 gpt-image-1.5、gpt-image-1、gpt-image-1-mini、chatgpt-image-latest 和 dall-e-2；本平台也可把网关模型名路由到 Azure、自建或 Gemini image-preview 渠道
ninteger否生成张数，默认 1，按模型支持生效
sizestring否输出尺寸，如 "auto"、"1024x1024"、"1536x1024"、"1024x1536"；Gemini image-preview 额外支持 2048x2048→2K、4096x4096→4K
qualitystring否质量："auto" / "high" / "medium" / "low"
backgroundstring否背景策略："auto" / "transparent" / "opaque"
input_fidelitystring否输入图保真度："high" / "low"，按 OpenAI GPT Image 支持生效
moderationstring否内容审核："auto" / "low"，按 OpenAI GPT Image 支持生效
output_formatstring否输出格式："png" / "jpeg" / "webp"
output_compressioninteger否压缩质量 0–100，仅对 jpeg / webp 输出有效
streamboolean否是否流式返回图片编辑事件，需 OpenAI 兼容上游支持
partial_imagesinteger否流式中间图数量，官方范围 0–3，仅 stream:true 时使用
response_formatstring否"url" / "b64_json"
userstring否终端用户标识，用于审计和风控
实现说明：OpenAI 渠道的 JSON 图片编辑请求会按 JSON 透传；multipart 请求会重新组装，兼容 image、image[] 和 image[n] 多图字段。Gemini image-preview 编辑请求会被转为 Gemini generateContent：prompt 变成文本 part，输入图和 mask 会下载或解码成 inlineData 图片 part，并设置 responseModalities=["TEXT","IMAGE"]。Gemini JSON 适配推荐使用 {"image":"https://..."} 或 {"images":["https://...","data:image/..."]} 这类字符串形式。

Responses API

POST /v1/responses

OpenAI Responses API 兼容端点，支持多轮对话、工具调用、结构化输出等高级功能。兼容 OpenAI Responses API。同时提供 /v1/responses/compact 端点用于紧凑式响应。

Responses API 是 OpenAI 新一代交互协议，相比 Chat Completions 提供了更丰富的内置工具（web_search、file_search、code_interpreter）和更简洁的状态管理模型。

请求参数

inputstring | InputItem[]是—输入内容：文本字符串或结构化的输入项数组。支持文本、图片、文件、函数调用结果、上一轮输出项等 OpenAI Responses 输入形态
includestring[]否—要求上游额外返回的数据，如 file_search_call.results、message.input_image.image_url、message.output_text.logprobs、reasoning.encrypted_content 等

常见问题

现象常见原因处理方式
model is required 请求体缺少 model 补上正确模型名
prompt is required 图片生成缺少 prompt 补提示词
无可用模型或无可用服务 模型名不可用、令牌权限不足或服务暂不可用 确认模型名称和令牌权限，必要时联系平台支持
Azure 返回不支持 response_format 请求包含当前模型不支持的 response_format 删除该字段，或按接口文档支持的返回格式处理
图片返回 b64_json 非 URL 默认返回 base64 客户端兼容 base64；如模型支持可传 response_format: "url"
请求超时 图片生成耗时较长 客户端超时建议设置 10 分钟以上
moderation_blocked 提示词触发安全策略 修改 prompt，避免违规内容
问题反馈：报错时请保存 X-Oneapi-Request-Id 响应头，并连同请求时间、模型名和错误信息一起提供给平台支持。

接入准备

  1. 进入平台首页，复制页面展示的 服务器地址 / API 地址。
  2. 进入 令牌管理，创建并保存 sk- 开头的 API 令牌。
  3. 在 模型广场 或 GET /v1/models 中确认当前令牌可用的模型名。
  4. 根据业务场景选择协议：文本走 Chat/Responses，图片走 Images，视频走 Video Task，检索走 Embedding/Rerank。
  5. 先用低成本、小请求量验证调用链路，再接入正式业务流量。

文本对话

确认模型名、messages 格式、流式开关和返回结构。

图片生成

确认 prompt、size、quality、返回 URL 或 base64 的处理方式。

视频生成

提交任务后保存 task_id，并按退避策略查询任务结果。

问题可能原因处理

403 Forbidden当前令牌不可访问该模型或不符合访问限制确认令牌可用模型、有效期和 IP 白名单
400 model is required请求体缺少 model补模型名，并确认模型在令牌权限内
无可用模型或无可用服务模型名不可用、令牌无权限或服务暂不可用确认模型名称，必要时联系平台支持
429 Too Many Requests请求过快、额度不足或触发频率限制降低频率，检查账户额度和令牌额度
视频长时间 in_progress视频生成耗时较长或任务排队按 5s、10s、20s、30s 退避轮询，保留 task_id

限制与建议

  • /v1/files、fine-tunes、图片 variations 等部分 OpenAI 端点当前未实现。
  • 同名参数是否生效取决于具体模型能力，平台会尽力按兼容协议转换。
  • 部分高级字段可能因模型能力或平台策略不被支持，请以实际响应为准。
  • 视频、Midjourney、Suno 等任务类接口必须按任务查询。
  • 价格展示和消耗记录以平台页面展示、令牌分组和任务实际用量为准。

平台功能指南

平台功能指南

面向普通用户的控制台操作说明，覆盖模型测试、令牌创建、用量查询、模型广场和个人设置。开发者接口调用请查看 API 接口文档，模型调用方式请查看 模型接入指南。

先建令牌

令牌是 API 调用凭证，可绑定分组、额度、过期时间、模型权限和 IP 白名单。

再选模型

模型广场用于查看可用模型、供应商、上下文、端点类型和计费方式。

最后查日志

使用日志记录请求模型、令牌分组、花费、状态和 request_id，便于查询问题。

控制台

模型对话

模型对话用于快速测试平台模型。选择用户分组后，可以按该分组的模型权限和折扣进行调试；开启图片地址后，可测试文本 + 图片的多模态对话。

参数作用建议
Temperature控制随机性和创造性总结、抽取类任务调低；创作类任务调高
Top P控制词汇选择范围越小越聚焦，越大越发散
Frequency Penalty减少重复表达长文本生成可适度调高
Presence Penalty鼓励引入新话题开放式讨论可适度调高
Max Tokens限制单次输出长度按业务所需设置，避免无意义消耗
Seed让相同输入更容易复现输出调试和回归测试时填写

数据看板

数据看板展示余额、历史消耗、请求次数、额度消耗、平均 RPM、平均 TPM 和模型消耗趋势。RPM 反映请求频率，TPM 反映 token 处理量，两者共同用于评估成本、限流和扩容策略。

令牌管理

令牌是调用 API 的核心凭证。创建令牌时需要填写名称、选择分组、设置有效期和额度，并按需配置模型限制与 IP 白名单。令牌生成后请立即保存，不要在聊天、工单或公开仓库中泄露。

安全建议：为不同应用创建独立令牌；临时测试令牌设置短有效期；疑似泄露时立即删除并重新创建。

使用日志

使用日志用于查看 API 调用记录，包括请求时间、令牌分组、模型、状态、花费和 request_id。普通用户只能查看自己的日志；如需反馈问题，可将 request_id 提供给平台支持。

绘图日志

绘图日志用于集中查看 Midjourney 等绘图任务。可按时间范围、任务 ID 查询，也可通过列设置调整表格字段，快速确认任务状态、耗时、Prompt 和结果图片。

模型广场

模型广场集中展示可用模型，支持按供应商、标签、令牌分组、计费类型和端点类型筛选。用户可查看模型名称、上下文、输入/输出限制、计费方式和能力说明，再决定令牌权限和调用模型。

区域用途
左侧筛选按供应商、标签、分组、计费类型和端点类型缩小范围
顶部搜索按模型名称快速定位
倍率/充值价格显示辅助理解模型价格和充值价格换算
模型卡片查看模型能力、上下文长度、计费方式和批量选择状态

个人设置

账号绑定

个人设置中可以管理账号信息和第三方绑定。平台可按实际配置支持邮箱、微信、GitHub、LinuxDo 等登录或绑定方式。

安全设置

安全设置用于修改密码、重置 API 密钥和开启两步验证。开启两步验证后，登录时需要输入密码和验证器应用生成的动态验证码。
